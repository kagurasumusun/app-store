# 実機検証手順

フェイクトランスポートの単体テストと CI ビルドでは「ワイヤ形式」と
「コンパイル」までしか保証できません。実際の Apple サーバー相手の成否は
この手順で確認します。各項目に期待結果を書いてあるので、上から順に
実施し、失敗したら「失敗時の記録」の形で情報を残してください。

## 準備

1. 署名付きビルドを実機（iOS 27）に入れる:
   ```bash
   DEVELOPMENT_TEAM=<TEAMID> bash Scripts/build_app.sh --device --sign
   bash Scripts/package_ipa.sh
   ```
   Xcode から直接インストールしても構いません。
2. テスト用の Apple Account を用意する
   （できれば購入履歴のあるものと、2FA 有効なもの）。
3. Console.app で端末ログを見られるようにしておくと追跡が楽です
   （フィルタ: プロセス名 `IpaStore`）。

## 1. サインイン（最重要）

SAP 署名つき認証が通るかの確認です。ここが失敗すると署名か
リクエスト形式のどちらかが想定とずれているため、最初に潰します。

- [ ] メール + パスワードでサインインできる
      → 期待: アカウントが追加され、ストアフロントがアカウントの地域になる
- [ ] 2FA アカウント: コード入力画面が出て、6 桁コードで完了する
- [ ] わざと間違ったパスワード → 資格情報エラーが表示され、落ちない
- [ ] （対象番号があれば）中国/インドの電話番号でサインインできる
- [ ] Simulator でも同じサインインができること
      （SAP は純ソフトウェア実装なので実機と同一に動くはず）

失敗パターンの切り分け:
- 403 が即座に返る／「HTTP 403」→ 署名が付いていないか形式が違う
- 200 で `MZFinance.BadLogin` 系 → 署名は通っている。資格情報側の問題
- タイムアウト → ネットワークか、リダイレクト処理の停滞

## 2. 検索・詳細

- [ ] 日本語・英語キーワードで検索できる
- [ ] ストアフロント切り替えで通貨・価格表示が変わる
- [ ] 詳細画面でスクリーンショット・評価・What's New が出る

## 3. 購入（無料）とダウンロード

- [ ] 未所有の無料アプリを「購入（自動）→ ダウンロード」まで通せる
- [ ] 進捗・速度・残り時間が更新され、完了後に「ダウンロード」タブの
      ファイル一覧へ入る
- [ ] 有料アプリ（未所有）は「購入できません」で止まる
- [ ] Files アプリから「IPAShelf で開く」で IPA を取り込める

## 4. インストール（初回のみ証明書手順）

証明書のインストールと信頼ONは iOS の仕様で設定アプリでの操作が必須
です（全アプリ共通で、アプリ内から完結させることはできません）。
アプリ側はプロファイル配布と「信頼されているか」の表示を行います。
古いビルドで作られた証明書/プロファイルが残っている端末では、
先に旧プロファイル（「IPAShelf Root CA」）を削除してから実施して
ください（証明書自体は起動時に自動で作り直されます）。

- [ ] 設定タブ「Install Root Certificate」→ Safari でプロファイルを
      ダウンロードできる
- [ ] 設定 › 一般 › VPN とデバイス管理 でインストールでき、
      設定 › 一般 › 情報 › 証明書信頼設定 で「IPAShelf Root CA」を
      オンにできる
- [ ] オンにしたあとアプリに戻ると、設定タブの「Trust on this
      device」が Trusted になる
- [ ] ダウンロード済みパッケージの「Install」でシートが開き、
      自動で iOS のインストール確認が出る
- [ ] インストールが完了し、ホーム画面で起動する
- [ ] 証明書を信頼していない状態では確認ダイアログが自動では出ず、
      シートの案内で信頼をONにして戻ると自動で確認が出る
- [ ] ダウンロード開始直後に画面をロックしてもキャンセル扱いに
      ならず、失敗した場合は「中断」として再試行で続きから再開できる

モバイル回線（Wi-Fi オフ）でも同じ手順で通るはずです
（配信は 127.0.0.1 のみ）。Safari で「接続できません」や
プロファイルのエラー（「PayloadContent が見つかりません」等）が
出た場合は、壊れた/古いプロファイルを掴んでいる可能性があるので、
設定アプリ側に残った旧「IPAShelf Root CA」プロファイルを削除し、
アプリから「Install Root Certificate」をもう一度試してください
（最新ビルドを入れ直した直後は特に）。それでも通らない場合は
シートの文言とステータス（Ready / Sending / Failed）を記録して
ください。

## 5. バージョン指定

- [ ] 所有アプリの詳細でバージョン一覧が取得できる
- [ ] 各行の表示バージョンとリリース日が（少し遅れて）埋まる
- [ ] 最新の行に「Latest」バッジが付く
- [ ] 旧ビルドを指定してダウンロードでき、ファイル一覧に別バージョン
      として残る
- [ ] 旧ビルドをインストールすると、実際にそのバージョンが入る

表示バージョンが埋まらない場合、バージョン指定ダウンロード応答の
メタデータに `bundleShortVersionString` が欠けている可能性があります。
対象のアプリ名とビルド ID を記録してください
（ダウンロード自体は ID だけで可能なはずです）。

## 6. 購入履歴

- [ ] 「購入済み」タブに所有アプリが新しい購入順で並ぶ
- [ ] スクロールで次ページが読み込まれる／ pull-to-refresh で再取得
- [ ] プラットフォームフィルタ（Mac など）が効く
- [ ] **配信終了して検索に出ないアプリ**が表示され、ダウンロードできる
- [ ] 行のダウンロードボタン、スワイプ、詳細遷移のいずれも機能する
- [ ] アカウントを切り替えると一覧・バージョン情報が前のアカウントの
      ものと混ざらない

## 7. レジューム

- [ ] 大きめのアプリのダウンロード中に機内モード ON→OFF、
      または「すべてキャンセル」→ 再試行で、0 からではなく
      途中から再開する（進捗が前回の位置から始まる）
- [ ] ダウンロード中にアプリを終了→再起動して再試行しても再開する
- [ ] 再開後のパッケージが MD5 検証を通り、インストールできる

## 8. トークン失効・エラー表示

ダウンロード用トークンが失効した場合、保存パスワードで自動的に
再サインイン（ローテート）して1回だけ再試行します。

- [ ] 長時間放置後に購入履歴／ダウンロードが（再サインインなしで）
      そのまま通る
- [ ] アカウント詳細の「Refresh Token」で手動ローテートができる
      （2FA が必要な場合はコード入力欄が出る）
- [ ] パスワード変更後は、エラー表示のうえでサインインし直すと回復する
- [ ] 機内モードではネットワークエラーの表示になり、落ちない
- [ ] 動作を連打（詳細→バージョン→ダウンロードを繰り返す等）しても
      「catalog lookup returned HTTP 429」の汎用エラーにならない
      （カタログ照合は最大 3 回まで待って再試行し、成功結果は
      10 分キャッシュする。それでも制限中の場合は、最新ビルドの
      ピンを断念して未ピンのままダウンロードを続行し、取得した
      IPA のプラットフォーム検証で最終判断する）

## 失敗時の記録

次の情報を添えて報告してください。再現と切り分けが一気に進みます。

1. 失敗した操作と画面に出た文言（そのまま）
2. 対象（アプリ名 / Bundle ID / 選択したビルド ID / プラットフォーム）
3. アカウントの地域（ストアフロント）。資格情報そのものは不要
4. エラーに含まれる `HTTPStatus` や Apple の `failureType` が
   画面やログに出ていればその値
5. 時刻（Apple 側の一過性障害との切り分け用）

> パスワード・トークンを含むログやスクリーンショットは共有しないでください。
